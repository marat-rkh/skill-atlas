# Scripted demo video

- **When:** 2026-09-30, 15:30–16:45
- **Where:** main checkout
- **Transcript:** `bfe5c71a-e4d4-4492-8a07-2e26fa8f9cfc`
- **Result:** `demo/` with `record.sh`, which writes `demo/out/skill-atlas-demo.mp4` (about 1:44, 1920×1080, H.264).
  Committed and pushed straight to `main`, without a PR, at the user's request.

## What happened

1. The user asked for a video that demos the main scenarios. We compared a real screen recording with a scripted one,
   and the user chose **scripted**: it can be re-recorded with one command after each change, doesn't take over the
   screen, and doesn't show desktop clutter.
2. **Terminal part:** [VHS](https://github.com/charmbracelet/vhs) with `cli.tape`. It shows the usage message, the flat
   map, `--group`, and `serve` printing its address. It uses `vercel-labs/agent-skills` (9 skills, which fit on one
   screen at font size 15).
3. **Browser part:** Playwright driving the installed Chrome (`channel: 'chrome'`) with `web.mjs`, recording against a
   running `skill-atlas serve`. Scenes: the start page, `/scan?repo=https://github.com/openai/skills` (44 skills,
   loads in about 2s), filter `design` (10 of 44), the grouping checkbox with the filter kept, then clearing the filter.
   The recording has no address bar, so each page gets a caption with the step and the URL, and each element is
   outlined before it's used.
4. The two parts were joined with ffmpeg.
5. The scripts were moved into `demo/`. `demo/record.sh [output.mp4]` does the whole thing: it builds the binary into
   `demo/out/bin`, runs `npm ci` if needed, records both parts and joins them. It takes about 2 minutes and needs port
   8080 free. `demo/node_modules/` and `demo/out/` are gitignored.

## Findings

- Playwright records the viewport at 1x and ignores `deviceScaleFactor`, adding padding instead. For a 1920×1080 video,
  use a 1920×1080 viewport and zoom the page to 150% with CSS in an init script.
- Chrome sends video frames only when the page repaints. On a still page the video sometimes kept a stale first frame
  (no caption, gray strip) or ended early. `web.mjs` fixes this with an invisible 2px CSS animation; six test runs in a
  row came out right.
- JetBrains/kotlin takes about 13s per scan, and every web request fetches the repo again (there's no caching). That's
  too slow for a demo, so `openai/skills` and `vercel-labs/agent-skills` were used instead.
- `openai/skills` has two skills named `openai-docs` in different directories. The map shows them as two identical
  entries, because it no longer shows each skill's path.

## Left open

- CI runs only on pull requests, so it didn't run on this push. `demo/` has no Go code, and the Go checks passed

- `vhs` (which brings `ffmpeg` and `ttyd`) was installed through Homebrew. Playwright's own ffmpeg is in
