## What happened

1. **Initial CLI in Kotlin** from `spec/cli.md`. The user asked not to overengineer; the first goal was a working run
   on `github.com/JetBrains/kotlin`. The app fetches only the file tree, then all `SKILL.md` files in one sparse-checkout
   batch (about 1s; checking out path by path took 27s). JetBrains/kotlin: 6 skills in about 5s. Commit `250cf31`.
2. **Language choice.** The user wants a nice terminal UI (colors, clickable links, folding). We compared Kotlin, Python +
   Textual, Go + Bubble Tea, TypeScript + Ink and Rust + Ratatui. The user chose Go.
3. **Migration to Go**, standard library only. The IntelliJ project was set up for GoLand (Go module `.iml`, shared run
   configuration), and the spec gained a "Technologies" section. Output matched the Kotlin version byte for byte on six
   repos. Go 1.26.6 was installed with Homebrew. Commit `e50f289`. Both commits were cherry-picked onto `main`.
4. **CI:** `.github/workflows/ci.yml` runs on every pull request and checks `gofmt`, `go vet`, `go build` and `go test`.
   Commit `a074302`.
5. **Tests:** 20 tests in three kinds: unit tests; integration tests with real git against local `file://` repos; and
   two end-to-end tests against github.com that `-short` skips (CI runs them). To make the code testable,
   `checkoutSkillFiles` now takes a remote URL and `main` calls `runCLI(args, stdout, stderr)`. PR #1 went green in 39s,
   and the user merged it.
6. **`AGENTS.md`** (definition of done, written by the user) was committed as `3aee40c`.
7. **Web interface.** The user chose Go's standard library (`net/http`, `html/template`, `embed`), as a local tool that
   shows the same map as the CLI. `spec/cli.md` became `spec/app.md`, with the CLI and the web as two presentations.
   Added `atlas.go` (shared scan), `text.go` (terminal rendering), `web.go` and `web/page.html`. `skill-atlas serve`
   listens on `127.0.0.1:8080`; a bad repo URL gives 400, and a failed fetch gives 502. 38 tests. At the user's request
   this was merged into `main` locally without a PR, as three commits plus merge `b1e54a9`.

## Decisions

- **Go instead of Kotlin:** it builds a single binary and has Bubble Tea for the interactive terminal UI planned later.
- **Repo URL in the query, `/scan?repo=<url>`:** this replaced `/scan/<url>`. A URL in the path gets its `//` merged,
  loses `?` and `#`, and has unclear encoding. POST was rejected because a scan only reads data and should be bookmarkable.
- **Server listens on the local machine only:** it's a local tool, and this stops other machines from triggering git
  fetches.

## Findings

- Branch protection can't be enabled: the repo is private on GitHub's free plan. CI runs on PRs but can't be a required
  check.
- CI runs only on pull requests, so pushing straight to `main` isn't tested by CI.
- A literal byte-order mark character in source broke the Go build twice. Use the `﻿` escape.
